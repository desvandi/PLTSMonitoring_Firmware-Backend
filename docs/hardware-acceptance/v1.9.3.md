## Prerequisites

1. **Device**: ESP32-WROOM-32 flashed with v1.9.3 firmware (the release-candidate commit)
2. **INA219**: Module at I²C address 0x40, R100 (0.1Ω) resistor REMOVED, external shunt 100A/75mV connected low-side
3. **Voltage Divider**: R1=190kΩ (battery+ → GPIO34), R2=10kΩ (GPIO34 → GND), 0.1µF ceramic cap parallel to R2
4. **Reference Meter**: Calibrated multimeter (voltage ±0.1V, current ±0.5A) OR clamp meter for cross-checking
5. **Load Bank**: Adjustable DC load capable of 1A → 150A (or multiple loads combined)
6. **Serial Monitor**: Connected at 115200 baud to observe INA219 init + PGA switch logs
7. **PWA**: Running in browser, connected to device WiFi, battery view visible

## Checklist (12 Criteria)

### Criterion 1: INA219 config register readback at boot

- [ ] Power on device, open Serial Monitor at 115200 baud
- [ ] Observe INA219 init log line: `[INA219 0x40] init: shunt=0.7500 mΩ, cal=0x..., sign=-1.0, pga=80mV`
- [ ] Observe config readback log: `[INA219 0x40] config readback OK: 0x0FFF (BRNG=0 16V, PGA=1 ±80mV, BADC=15, SADC=15, MODE=7)`
- [ ] Verify PGA=1 (decimal for 0b01 = ±80mV) — NOT PGA=3 (±320mV)
- [ ] Verify BADC=15 (12-bit/128-sample) — NOT a RESERVED value
- [ ] Verify SADC=15 (12-bit/128-sample) — NOT a RESERVED value
- [ ] Verify MODE=7 (shunt+bus continuous) — NOT MODE=3 (triggered/one-shot)
- [ ] Record `configReadbackHex` = "0x0FFF" in evidence JSON
- [ ] Record `configReadbackPgaBits` = 1 in evidence JSON

**Expected**: Readback matches `0x0FFF` exactly. PGA bits = 01 (±80mV). BADC/SADC = 15 (12-bit/128-sample). MODE = 7 (continuous). This proves the register write succeeded and the hardware is in the correct mode.

**If FAIL**: Do not proceed. The I²C write or the register constant is wrong. Check wiring + Config.h.

### Criterion 2: Low-current accuracy (1–2A standby, ±80mV mode)

- [ ] Set load bank to 1.5A
- [ ] Wait 10 seconds for EMA to settle
- [ ] Read PWA battery current display (should show 2 decimal places, e.g., "1.47 A")
- [ ] Read reference meter current
- [ ] Compute delta = |PWA - reference|
- [ ] Verify delta ≤ 0.5A (acceptance tolerance)
- [ ] Verify PWA PGA indicator shows "80mV"
- [ ] Record `lowCurrentPwa` and `lowCurrentRef` in evidence JSON

**Expected**: PWA current within ±0.5A of reference meter. PGA mode = "80mV". The ±80mV range has 10µV resolution (0.013A at 0.75mΩ), so 2-decimal precision is honest.

### Criterion 3: Mid-current accuracy (50A, ±80mV mode)

- [ ] Set load bank to 50A
- [ ] Wait 10 seconds for settling + any PGA switch transitions
- [ ] Read PWA battery current (should show 1 decimal place, e.g., "50.3 A")
- [ ] Read reference meter current
- [ ] Compute delta = |PWA - reference|
- [ ] Verify delta ≤ 1.0A (acceptance tolerance at higher current)
- [ ] Verify PWA PGA indicator still shows "80mV" (50A < 100A threshold)
- [ ] Record `midCurrentPwa` and `midCurrentRef` in evidence JSON

**Expected**: PWA within ±1.0A. PGA mode = "80mV" (no switch yet — 50A < 100A).

### Criterion 4: Pre-transition current (90A, ±80mV mode, hysteresis lower bound)

- [ ] Set load bank to 90A
- [ ] Wait 10 seconds
- [ ] Read PWA battery current
- [ ] Read reference meter current
- [ ] Verify PWA PGA indicator shows "80mV" (90A is at the hysteresis lower bound but still in 80mV mode)
- [ ] Record `preTransitionPwa` and `preTransitionRef` in evidence JSON

**Expected**: PGA = "80mV". Current reading within ±1.5A of reference.

### Criterion 5: PGA UP transition (100A → switch to ±160mV)

- [ ] Increase load from 90A to 105A (cross the 100A threshold)
- [ ] Watch Serial Monitor for: `[INA219 0x40] PGA 80mV → 160mV (I=105.0A ≥ 100A threshold)`
- [ ] Watch for: `[INA219 0x40] PGA settling — sample discarded (pga=160mV)` (one discarded sample)
- [ ] Wait 5 seconds for settling
- [ ] Verify PWA PGA indicator now shows "160mV"
- [ ] Read PWA battery current (should show 0 decimal places, e.g., "105 A")
- [ ] Read reference meter current
- [ ] Verify no false spike/NaN/discontinuity in the PWA current reading during transition
- [ ] Record `transitionUpObserved` = true, `transitionUpPwa`, `transitionUpRef` in evidence JSON

**Expected**: Serial log shows PGA switch. PWA PGA indicator changes to "160mV". One sample discarded. No false spike. Current reading is continuous (no NaN/zero jump).

### Criterion 6: Peak current measurement (120–150A, ±160mV mode)

- [ ] Increase load to 120A
- [ ] Wait 10 seconds
- [ ] Read PWA battery current
- [ ] Read reference meter current
- [ ] Verify delta ≤ 2.0A (acceptance tolerance at peak)
- [ ] Verify PWA PGA indicator shows "160mV"
- [ ] Record `peakCurrent120Pwa` and `peakCurrent120Ref`

- [ ] Increase load to 150A (if load bank supports it)
- [ ] Wait 10 seconds
- [ ] Read PWA battery current
- [ ] Read reference meter current
- [ ] Verify delta ≤ 3.0A (acceptance tolerance at absolute peak)
- [ ] Verify NO saturation (current should read ~150A, NOT cap at ~106A which would indicate ±80mV mode is still active)
- [ ] Record `peakCurrent150Pwa` and `peakCurrent150Ref`

**Expected**: 150A reads correctly (within ±3A). If reading caps at ~106A, the PGA switch is NOT working — this is the v1.9.0 bug symptom. The fact that 150A reads correctly proves the ±160mV mode is active.

### Criterion 7: PGA DOWN transition (90A → switch back to ±80mV)

- [ ] Decrease load from 150A to 85A (cross the 90A hysteresis lower threshold)
- [ ] Watch Serial Monitor for: `[INA219 0x40] PGA 160mV → 80mV (I=85.0A < 90A threshold)`
- [ ] Watch for: `[INA219 0x40] PGA settling — sample discarded (pga=80mV)`
- [ ] Wait 5 seconds
- [ ] Verify PWA PGA indicator now shows "80mV"
- [ ] Verify no false spike/NaN during transition
- [ ] Record `transitionDownObserved` = true, `transitionDownPwa`, `transitionDownRef`

**Expected**: Serial log shows PGA switch back to 80mV. PWA indicator changes. One sample discarded. No discontinuity.

### Criterion 8: Hysteresis stability (load hovering at 95A)

- [ ] Set load to 95A (between 90A lower and 100A upper threshold)
- [ ] Hold for 30 seconds
- [ ] Observe Serial Monitor — should NOT see rapid PGA switching (chattering)
- [ ] Count PGA switch events in 30 seconds: should be 0 (mode should stay in whatever it was)
- [ ] Record `hysteresisChatterCount` = 0

**Expected**: No chattering. The 10A hysteresis gap (90A/100A) prevents oscillation. If chatter count > 2, the hysteresis is not working.

### Criterion 9: Current sign correctness (charging vs discharging)

- [ ] With load drawing current (discharging): verify PWA shows NEGATIVE current (e.g., "-50.3 A") or direction = "DISCHARGING"
- [ ] With charger pushing current (charging, if available): verify PWA shows POSITIVE current (e.g., "+10.5 A") or direction = "CHARGING"
- [ ] Verify sign is consistent with the INA219_SIGN_CORRECTION = -1.0 in Config.h
- [ ] Record `dischargeSignCorrect` = true, `chargeSignCorrect` (if tested)

**Expected**: Discharge = negative, charging = positive. If signs are flipped, the INA219 VIN+/VIN- wiring is reversed — swap the shunt leads OR change INA219_SIGN_CORRECTION to +1.0.

### Criterion 10: Voltage divider accuracy (190k/10k, 20:1 ratio)

- [ ] Measure battery voltage with reference multimeter at the battery terminals
- [ ] Read PWA battery voltage display
- [ ] Compute delta = |PWA - reference|
- [ ] Verify delta ≤ 0.5V (acceptance tolerance at full pack voltage)
- [ ] Test at multiple voltage levels if possible (e.g., 42V, 50V, 57.5V)
- [ ] If delta > 0.5V: adjust `ADC_FINE_TUNE` in Config.h = (reference / PWA_reading), rebuild, re-test
- [ ] Record `voltagePwa`, `voltageRef`, `voltageDelta` in evidence JSON
- [ ] Record `adcFineTuneApplied` (final value after calibration, default 1.0)

**Expected**: PWA voltage within ±0.5V of multimeter. If not, calibrate ADC_FINE_TUNE. The 190kΩ/10kΩ divider with ±5% resistors can produce up to ±2V error at 57.5V without calibration.

### Criterion 11: Power calculation correctness (V × I)

- [ ] At a known load (e.g., 50A at 52V = 2600W):
- [ ] Read PWA battery power display
- [ ] Compute expected power = voltage × current
- [ ] Verify PWA power matches expected within ±5% (e.g., 2600W ± 130W)
- [ ] Record `powerPwa`, `powerExpected`, `powerDeltaPct`

**Expected**: PWA power within ±5% of V×I. Power is derived (busV × currentA), so this validates both voltage and current measurements are consistent.

### Criterion 12: Telemetry pga_mode field correctness

- [ ] At 50A (±80mV mode): verify PWA PGA indicator = "80mV" AND Google Sheet `ina219_pga_mode` column = "80mV"
- [ ] At 120A (±160mV mode): verify PWA PGA indicator = "160mV" AND Google Sheet `ina219_pga_mode` column = "160mV"
- [ ] Verify the telemetry field matches the actual hardware register state (cross-reference with Serial Monitor readback log)
- [ ] Record `telemetryPgaModeMatchesHardware` = true

**Expected**: The `pga_mode` telemetry field (PWA + Google Sheet) matches the actual INA219 config register state shown in Serial Monitor. This is the end-to-end proof that the register readback + telemetry + PWA display chain is consistent.

## Key Acceptance Principle

**Unit tests prove the source code is correct. Hardware acceptance proves the MEASUREMENT is correct.**

The v1.9.0 bug (inverted PGA bit-mapping) passed unit tests because the unit test only checked the constant values, not the actual hardware register state. The v1.9.2 fix adds register readback verification, but even that only proves the register write succeeded — it does NOT prove the current reading is accurate.

Only Criterion 2 (1.5A accuracy), Criterion 6 (150A no saturation), and Criterion 10 (voltage accuracy) can prove measurement correctness. These require a physical reference meter and are NOT optional.
