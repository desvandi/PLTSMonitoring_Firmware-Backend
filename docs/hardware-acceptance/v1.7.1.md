## How to use this template

1. Copy this file to `docs/hardware-acceptance/v1.7.1.md` (already done — this IS that file).
2. Fill in ALL checklist items with actual observed values (not just checked boxes —
   include observed values where the check says "Observed:").
3. Get sign-off from Test Engineer, Reviewer, and Release Manager.
4. Commit this completed file to the repo.
5. Tag the release: `git tag -s v1.7.1 -m "Release v1.7.1"`.
6. Push the tag: `git push origin v1.7.1`.
7. CI will detect the tag, run the full pipeline, and create a GitHub Release.
   Because this file exists, the release will be marked as STABLE (not pre-release).
8. Attach this completed file to the GitHub Release as documentation.

**Without this file, the CI `release-publish` job marks the release as
pre-release (beta) — it CANNOT be promoted to fleet OTA.**
