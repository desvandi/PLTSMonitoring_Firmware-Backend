## What's New in v1.8.0

- 8-channel relay control via PCF8574 I²C expander
- RelayController with safety supervisor (maxOnTime, minOnTime, antiChatter)
- 5-state lockout (NORMAL→TRIPPED→ACKNOWLEDGED→CLEARED→ARMED)
- Interlock engine (mutual exclusion + dead time)
- REST API: `/api/relays`, `/api/relays/{id}/{on|off|pulse}`, `/api/relays/all_off`
- MQTT command dispatch via canonical pipeline
- E-WAVE safety cascade (trip → all relay channels OFF)
- PWA relay control view with 3-tier state model
- Command queue for single-threaded mutation

## Checklist

### 1. Boot & First-Run Behavior
- [ ] Device boots within 5 s
- [ ] FIRMWARE_VERSION = 1.8.0
- [ ] WiFi connects within 30 s
- [ ] NTP syncs within 60 s
- [ ] MQTT connects (TLS)
- [ ] Boot health check passes after 60 s

### 2. Sensor Telemetry (regression — must still pass)
- [ ] Voltage within ±0.2 V
- [ ] Current within ±0.2 A
- [ ] Temperature within ±2 °C
- [ ] Telemetry published at configured cadence
- [ ] PWA status page shows live data

### 3. Alarm Lifecycle (regression)
- [ ] Low-voltage alarm triggers
- [ ] PWA shows alarm
- [ ] POST /api/alarms/{code}/acknowledge returns 200
- [ ] Alarm moves to history

### 4. OTA Update — REST Path (regression + new lifecycle)
- [ ] Upload signed binary via POST /api/ota
- [ ] SHA-256 verification passes
- [ ] Ed25519 signature verification passes
- [ ] Device reboots into new image
- [ ] Lifecycle events: ACCEPTED, DOWNLOADING, VERIFIED, FLASHED, ACTIVATED

### 5. OTA Update — MQTT Path (regression + new lifecycle)
- [ ] Trigger OTA via MQTT ota.start
- [ ] Lifecycle events emitted to MQTT: ACCEPTED, DOWNLOADING, VERIFIED, FLASHED, ACTIVATED
- [ ] jobId correlation verified in GAS OtaEvents

### 6. OTA Rollback (regression)
- [ ] Upload binary that fails boot health check
- [ ] Bootloader reverts to previous image
- [ ] ROLLBACK lifecycle event emitted with correct failed version

### 7. 8-Channel Relay — Physical Channel Tests (NEW)
- [ ] CH0 ON → physical relay click audible
- [ ] CH0 OFF → physical relay release
- [ ] CH1 ON/OFF
- [ ] CH2 ON/OFF
- [ ] CH3 ON/OFF
- [ ] CH4 ON/OFF
- [ ] CH5 ON/OFF
- [ ] CH6 ON/OFF
- [ ] CH7 ON/OFF

### 8. 8-Channel Relay — Boot Safety (NEW)
- [ ] Boot → ALL relay channels OFF (no glitch ON)
- [ ] Power cycle → ALL relay channels OFF
- [ ] Watchdog reset → ALL relay channels OFF
- [ ] Brownout → ALL relay channels OFF

### 9. 8-Channel Relay — I²C Fault Handling (NEW)
- [ ] Disconnect PCF8574 I²C → relay driver unavailable
- [ ] POST relay ON → fault=true, reportedState=unchanged, RELAY_FAULT alarm
- [ ] Reconnect PCF8574 → driver recovers on next boot

### 10. 8-Channel Relay — E-WAVE Cascade (NEW)
- [ ] Trigger E-WAVE trip (e.g., low voltage)
- [ ] ALL 8 relay channels forced OFF immediately
- [ ] Relay channels cannot be turned ON while E-WAVE is tripped

### 11. 8-Channel Relay — maxOnTime (NEW)
- [ ] Configure maxOnTime = 10s for CH0
- [ ] Turn CH0 ON
- [ ] After 10s → FORCE OFF automatically
- [ ] RELAY_MAX_ON_TIME alarm raised
- [ ] CH0 locked (TRIPPED state)
- [ ] Acknowledge → CLEAR → re-arm required

### 12. 8-Channel Relay — Interlock (NEW)
- [ ] Configure interlock group: CH0 + CH1 (mutual exclusion)
- [ ] Turn CH0 ON → CH1 ON blocked (interlock violation)
- [ ] Turn CH0 OFF → dead time → CH1 ON allowed

### 13. 8-Channel Relay — Pulse (NEW)
- [ ] POST /api/relays/0/pulse { durationMs: 2000 }
- [ ] CH0 turns ON
- [ ] After 2s → CH0 turns OFF automatically
- [ ] Pulse with duration < minOnTime → rejected

### 14. 8-Channel Relay — REST Commands (NEW)
- [ ] GET /api/relays → 8 channels with state
- [ ] POST /api/relays/0/on → 200 EXECUTED
- [ ] POST /api/relays/0/off → 200 EXECUTED
- [ ] POST /api/relays/all_off → 200 with per-channel result
- [ ] Duplicate requestId → 200 with previous ACK (idempotent)

### 15. 8-Channel Relay — MQTT Commands (NEW)
- [ ] MQTT relay on command → relay turns ON
- [ ] MQTT relay off command → relay turns OFF
- [ ] MQTT + REST produce identical canonical hash (dedup)

### 16. 8-Channel Relay — Reconnect Reconciliation (NEW)
- [ ] Turn relay ON via REST
- [ ] Disconnect WiFi → command timeout → state UNKNOWN (not FAILED)
- [ ] Reconnect WiFi → GET /api/relays → reconcile state
- [ ] No blind retry

### 17. Emergency Relay (regression — E-WAVE)

- [ ] E-stop → emergency trip
